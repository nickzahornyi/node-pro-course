# ADR-001: Marketplace data layer

Status: accepted for HW-12.

User stories:

- A buyer views their orders for a selected date range (q1).
- An operator views the latest orders awaiting payment (q2).
- A buyer finds a product by name regardless of letter case (q3).
- A seller owns products; a buyer creates an order containing products from sellers.

Four tables implement these relationships with four foreign keys. Identity bigint keys
avoid serial; timestamps carry time zones. Money uses exact numeric with two decimal places.
Order items retain the price at purchase, independently of the current product price.
The order total is a stored aggregate: future transaction work must update it atomically
with items; the seed already makes the aggregate consistent.

The existing HTTP contract uses integer cents; a future persistence adapter converts
numeric amounts to cents exactly (without floating-point arithmetic). HW-12 prepares
the SQL layer; existing products/orders handlers remain in-memory until persistence work.
The three queries model the API use cases above, not newly implemented HTTP endpoints.

Seed: 50,000 users, 20,000 products, 200,000 orders and 400,000 order items;
statuses are pending 1%, cancelled 5%, paid 20%, shipped 74%.
Dates and distributions are deterministic to make the comparison reproducible.

Three query optimization indexes are added in indexes.sql, one per measured query.
The initial schema enforces case-insensitive email uniqueness with a unique lower(email)
index; q3 therefore searches products by lower(name), keeping its baseline a Seq Scan.
The q1 interval is March 2026, a subset of the seeded January–May period.

The initial schema also indexes products.seller_id and order_items.product_id for
parent DELETE/UPDATE checks. order_items.order_id is covered by the leading column
of UNIQUE(order_id, product_id); orders.user_id is covered by the q1 composite index
after indexes.sql. PK/UNIQUE and FK-support indexes are justified independently of
their usage by these three SELECT queries. Production setup must apply both SQL files.
